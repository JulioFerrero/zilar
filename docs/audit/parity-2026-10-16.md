# Phone parity re-check, 2026-10-10 → 2026-10-16

This file re-checks, for every user-facing web change merged in the window
**2026-10-10 .. 2026-10-16**, whether the phone app (one React Native codebase,
so phone means Android and iOS) has the same feature.

It replaces `docs/audit/mobile-parity-gaps.md` (2026-10-05), which covered only
tools, routines, the activity feed, the `@mention` picker and two dialogs.

The audit is read-only: no source file was changed.

## How the scope was chosen

The window holds **773 merged rows** in `work/BOARD.md`. Most are the
"simplify", size-split, test-cut, mock-sweep, Effect/SQL and deploy waves, which
are internal (server-only, docs, tooling or size splits) and are skipped per the
task spec. This file covers the **user-facing web changes** in the window: a
change a person can see or do in the web app.

Conventions:

- Paths are relative to the repo root.
- **Web** is `apps/web/src`; **phone** is `apps/mobile/src`; shared logic is
  `packages/client-core`, `packages/chat-core`, `packages/api-contract`.
- Phone evidence is a `path:line` I (or a scoped search I ran) opened. The
  "Web (file)" column names the primary web file the task touched (taken from
  the task file); it is a file, not a line, because the acceptance criterion
  requires the *phone* line.
- `present` = the phone has the feature; `partial` = it exists but a named part
  is missing; `missing` = no phone equivalent found.
- "phone-only by nature" marks a web feature that cannot apply to a phone
  (hardware keyboard, mouse wheel/trackpad). These are not counted as gaps.

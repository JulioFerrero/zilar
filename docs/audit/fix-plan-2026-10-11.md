# Fix plan after the 2026-10-11 audits

Four Fable audits, docs only, with findings verified by code reading and, for some, spot-checked by the lead:

| Audit | Doc | P0 | P1 | P2 |
| --- | --- | --- | --- | --- |
| Message pipeline | `message-pipeline-audit.md` | 4 | 6 | 3 |
| Social graph and permissions | `social-graph-audit.md` | 2 | 4 | 5 |
| Security and privacy | `security-audit.md` | 0 | 4 | 11 |
| Features and UI state | `features-ui-audit.md` | 0 | 4 | 11 |

The lead spot-checked these against the code:
- MP-4: the text send is swallowed, and there are no SM ack or fail listeners;
- MP-5: the preview is only filled when empty;
- SG-1: a block only inserts a `user_blocks` row;
- SEC-2: `/xmpp-ws/*` strips the prefix and proxies all of ejabberd's `:5280`, including `/api`;
- UI-1: a reply sends the local id and the receiver matches by exact id.

Task ids in brackets name the fix in its audit doc: MP-Fn, SG-n, SEC-Fn, UI-Fn.

## Wave 1: running (message pipeline P0s)

- **T-1151, MP-F1:** mobile background suspend and wake.
- **T-1152, MP-F2:** push enable on every session.
- **T-1153, MP-F4:** honest sent tick and an outbox.
- **T-1154, MP-F5:** a server group-push notifier.
- **T-1155, MP-F6:** `notify_on: messages`, and the scan goes oldest-first within a 10-minute window.

## Wave 2: security and privacy quick wins (small, server and deploy only)

- **SEC-F2:** proxy only the ejabberd WebSocket path at both Caddy edges, so the admin API is no longer public.
- **SEC-F3:** grant the search role only `archive`. Production also needs one `REVOKE`, which Julio runs in the Coolify terminal.
- **SEC-F1:** serve uploaded "images" with `Content-Disposition` and a strict CSP, or `attachment` for SVG.
- **SEC-F4:** add `TRUSTED_PROXY_HOPS` and the missing env to the Coolify compose.
- **SG-1:** a block really blocks: drop the contact pair and the roster items, and filter the lists, search and push both ways.
- **SG-2:** strangers' DMs. **Julio decides** (see below).

## Wave 3: correctness users see every day

- **MP-F3:** catch-up after a reconnect, plus server-side unread and last message in `/api/chats`. Needs a new `chat_reads` table, so it runs as the only schema task at that time.
- **MP-F7:** a token 401 during a reconnect is retried.
- **MP-F8:** the delivered tick (XEP-0184), with sent, delivered and read states (Julio said yes).
- **UI-F1:** replies reference the stable origin id, so quotes show on the other device.
- **UI-F2:** the displayed marker only goes out for a chat that is open and visible; `closeChat` clears `pendingOpenChatId`.
- **UI-F3:** my reply from another device clears unread.
- **UI-F4:** last seen comes from `<delay/>` and survives the refresh.
- **UI-F5:** typing is tracked per sender in groups.

## Wave 4: the rest

- **SG-3 to SG-8:**

## Rules for every fix task
- Each task follows its audit section, with the `file:line` citations re-checked before launch.
- At most 400 lines per file. Tests only for auth and keys, permissions, and the message pipeline.
- The lead checks each one live (web, or Julio's phone with a new APK) before calling it done.

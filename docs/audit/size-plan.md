# File size and duplication plan (2026-10-10)

T-0936. Julio, 2026-10-10: "I also see 1000+ line files! … we need to find a way to reduce the number of lines in files, reuse code". He picked a **400-line limit**.

This is a read-only audit. It changes no code, and no line numbers below are copied from another report: every `file:line` was read in this worktree (branch `task/T-0936-size-dup-audit`). The overlapping plans are `docs/audit/simplify-plan.md` (the programme this feeds) and `docs/STORE_CORE_PLAN.md` (the client-core migration already underway). Mock code is out of scope (T-0935, `docs/audit/mock-plan.md`).

## 0. Summary

- **Scope:** `apps/*/src` and `packages/*/src`, without tests, `.d.ts`, `routes.expected.ts`, `test-support.ts`, `test-harness.ts` or mocks. **119 files are over 400 lines, for 78,831 lines**: 15 over 1,000, 36 between 601 and 1,000, 68 between 401 and 600.
- **Duplication is small at the 30-line bar.** jscpd finds 26 clone pairs (**1,320 duplicated lines**) with `--min-lines 30`, and 12 pairs with `--min-tokens 150`; the union is 33 pairs. The big web↔mobile and store copies the 2026-10-09 audit found are already gone (they were extracted to `packages/chat-core` and `packages/client-core/src/store`); what is left is UI markup inside one app, plus server boilerplate.
- **Splitting is mostly relocation.** The plans below move about **72,900 lines** into feature files (net 0) and **remove about 5,900 lines** of repetition and dead scaffolding. That is separate from the ~18–20k lines the simplify plan already removes by sharing `runSql`, the error envelope, the API contract and the store core; those are counted once, in the simplify plan.
- **Nothing here changes behaviour and nothing here adds a test.**

### 1.3 Where the copies go

- **Web UI (groups 2, 5, 6, 7, 9, 10, 18, 23):** stay in `apps/web/src/components`, in a shared local sub-component. They are DOM markup; React Native cannot reuse them.
- **Mobile UI (groups 1, 3, 11, 12, 17, 19, 20, 22, 24, 31):** stay in `apps/mobile/src/components`, in a shared local sub-component or in the mobile UI kit (`apps/mobile/src/components/ui`). No cross-app reuse.
- **Web↔mobile (groups 4, 8, 15, 16):** only the *pure logic* is shareable. `AuthFlow` (group 8) keeps a per-app markup but moves its step/validation table to `packages/chat-core`; the panels (groups 4, 15, 16) are markup-only, so each app dedupes inside itself. This is the whole story of cross-app duplication now — the store and helpers already moved (see the note in §2).
- **Server (groups 13, 14, 21, 25, 26, 27, 28, 29, 30, 32, 33):** `voice/api.ts:133-171` is the one upload handler the avatars, backgrounds and stickers APIs each copy; it and the error-envelope copies go to the shared handler from `simplify-plan` §2.2/§2.4, the membership query to `apps/server/src/groups/access.ts` (§2.6), the crypto envelope to the shared crypto helper (§2.7), and the indexers/agents/search clones to local sub-helpers.

## 3. The line-count lint rule

**oxlint supports `max-lines`.** oxlint 1.85.0 (the repo devDependency) defines it in `node_modules/oxlint/configuration_schema.json` (`definitions.MaxLinesConfig` with `max`, `skipBlankLines`, `skipComments`), next to `max-lines-per-function`. Verified in this worktree:

```
$ node_modules/.bin/oxlint -c <cfg with {"rules":{"max-lines":["warn",{"max":400}]}}> <450-line file>
.../big.ts:450:25: warning eslint(max-lines): File has too many lines (450). help: Maximum allowed is 400.
exit=0
```

So the rule exists, counts the whole file, and a warning does not fail the gate.

**The exact config** to add to `.oxlintrc.json` (this task changes no code, so it is a recommendation):

```jsonc
{
  "rules": {
    // A warning at 400 for every source file.
    "max-lines": ["warn", { "max": 400, "skipBlankLines": false, "skipComments": false }]
  },
  "overrides": [
    // keep the existing apps/mobile/src/app/**/*.tsx react/rules-of-hooks override
    {
      "files": [
        "**/*.test.ts", "**/*.test.tsx", "**/*.spec.ts", "**/*.spec.tsx",
        "**/*.test-harness.ts", "**/test-support.ts", "**/routes.expected.ts"
      ],
      "rules": { "max-lines": "off" }
    },
    {
      "files": [
        "**/mock/**", "**/mockStore.ts",
        "apps/mobile/src/store/chat-store.ts",
        "apps/mobile/src/lib/emoji-data.ts",
        "**/*.d.ts"
      ],
      "rules": { "max-lines": "off" }
    }
  ]
}
```

- `skipBlankLines` and `skipComments` stay `false` so the limit matches the raw `wc -l` numbers in this document, and moving code cannot game the rule by padding blank lines.
- **Tests** (`.test.*`, `.spec.*`, `test-harness`, `test-support`, `routes.expected.ts`) and **mocks** (`apps/web/src/mock/**`, `apps/web/src/store/mockStore.ts`, `apps/mobile/src/mock/**`, `apps/mobile/src/store/chat-store.ts`) are `off`, because their splits belong to T-0935 and the test-cuts tasks, not here.
- **Generated/data files** are `off`: the only >400-line one is `apps/mobile/src/lib/emoji-data.ts` (a hand-maintained emoji table; its split plan keeps the table as data and lints only `emoji-recents.ts`). `.d.ts` and `routes.expected.ts` are generated/snapshotted.
- **Warning first, then error: yes.** An `"error"` today would fail the gate on the 119 files above. Land it as `"warn"`, burn the list down, then flip the single `"warn"` to `"error"` when the count reaches zero. `pnpm gate` already runs lint, so the warning count is the burn-down. `max-lines-per-function` also exists but is out of scope: the request was a per-file limit.

## 4. The task split

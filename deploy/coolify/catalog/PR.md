# Zilar's Coolify catalog submission (demo)

These are the two upstream pull requests we would open to add Zilar to Coolify's
one-click catalog, written exactly as we would submit them. This folder is a
demo only: nothing here is merged, and no install reads it. The submission
waits for Zilar to reach 1,000 GitHub stars (it has 0 today).

The template PR goes to `coollabsio/coolify` (base branch `next`); the docs PR
goes to `coollabsio/coolify-docs`. The local files under `coolify/` and
`coolify-docs/` mirror the exact paths each PR changes.

---

## PR 1 — template PR (`coollabsio/coolify`, base `next`)

**Title:** `feat(service): add zilar`

**Branch:** `add-zilar`

**Body:**

### What is Zilar?

Zilar is a self-hosted chat app where people and AI agents talk in the same DMs
and groups. This template deploys the whole stack — XMPP server (ejabberd), a
TypeScript backend and a web app — behind one Coolify-routed domain, so the only
thing a user sets is the domain. Sign-in codes are sent by email, and a
first-run screen collects the mail key in the browser, so there is no terminal
step.

### Files

- `templates/compose/zilar.yaml` — the Compose stack.
- `svgs/zilar.svg` — the service logo.

The Compose file keeps Coolify's conventions: `SERVICE_PASSWORD_*` values are
generated and shared, `SERVICE_URL_WEB`/`SERVICE_FQDN_WEB` derive the public
domain, `restart` is left to Coolify's default, and image tags are pinned
(`v0.2.0`) rather than floating.

### How it was tested

Rehearsed live on Coolify 4.4.6, on a throwaway project and domain with AI
computers off:

- all 9 `SERVICE_PASSWORD_*` values were generated by Coolify, and
  `SERVICE_FQDN_WEB` followed the domain change;
- the four containers came up healthy in under 2 minutes with 0 restarts;
- `desk-agent` and `desk-egress` were not created, so Coolify honours the
  `desks` profile;
- over a real Let's Encrypt certificate: `/health` returned 200, `/api/me`
  returned 401, `/` returned 200 HTML, `/xmpp-ws/ws` upgraded with 101, and
  `/xmpp-ws/api/status` returned 404 (ejabberd's admin API is not exposed);
- 0 level-50 server errors in the logs.

### Notes for reviewers

- The two desk services are behind `profiles: ['desks']` and are off by default.
  Turning them on needs host preparation (gVisor plus a shared memory-pool
  slice) and runs `desk-agent` privileged with the Docker socket; both are only
  reached once the user opts in. While off, each container's guard exits 0, so
  neither is created or left running.
- The pinned jail image is a user-supplied digest; the desk services refuse to
  start without it, which is said clearly in their logs.
- Companion docs PR: `coollabsio/coolify-docs` — `docs(services): add zilar`
  (adds the service page and its logo).
